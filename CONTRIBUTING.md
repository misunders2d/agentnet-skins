# Contributing a skin

Thank you for making AgentNet look and feel different. A skin here can reach every AgentNet user through the in-app gallery, and it runs with the page’s full trust, so contributions are reviewed carefully.

## Make it

1. Pick the kind (details in [docs/CREATING.md](docs/CREATING.md)):
   - **Theme-only overlay**: Comic in your colours and fonts (`brand.tsx` + `theme.css`).
   - **Overlay skin**: Comic’s interface with any of its slots replaced. Start here unless the interaction itself must change.
   - **Standalone skin**: a different interface on the [skin contract](https://github.com/misunders2d/agentnet/blob/0859f1881762ff29c74d7d3eab4b0dcccfe2808d/docs/UI_SKINS.md) alone.
2. `npm ci`, then `npm run new-skin -- <id> "Name"` (add `--standalone` for a standalone skin). Overlays need the pinned AgentNet checkout: set `AGENTNET_SOURCE=/path/to/agentnet` or let the scripts clone it.
3. Offer a reason to choose it: a distinct layout, interaction or coherent playful experience. A recolor alone is a theme variant; label it that way.

## Test it

```sh
npm run build && npm run check && npm test
```

`npm test` prints which suites ran for each skin. Fix every failure; a skipped suite is not a pass. Tests use a disposable company on your machine and never touch your own AgentNet. Physical phones, OS keyboards, live Google consent and real models are not covered; say what you checked by hand.

## Preview it

`npm run previews -- <id>` renders the real skin on the pinned AgentNet: desktop and phone, light and dark, with an invented company. Look at every image. Previews:

- use invented people, companies and messages only, never names, photos or identities of real people (including the maintainers’ coworkers or contacts);
- show no keys, tokens, URLs with tokens, file paths or private data;
- are real renderings of the current code, never mockups; label concept art separately;
- are refreshed whenever visible behavior changes.

## Submit it

Open a pull request with `skins/<id>/` (source, `skin.json`, `gallery.json`, `README.md`, `previews/`), the root catalogue line, and `published/` regenerated by `npm run publish`. Describe the change, the tests you ran and anything you could not verify. Follow the [checklist](.github/pull_request_template.md).

Only a published GitHub release reaches the gallery; maintainers create releases after review.

## Review rules

- **Maintainers read every line.** A skin can read every chat and act as the person using it. Code that fetches `/api` or `/events` itself, reads AgentNet’s page globals, writes outside its root, loads remote code, fonts or images, uses `eval` or inline styles, phones home, or hides trust warnings, receipts or permission wording is refused.
- **No trademarks or real people.** No brand logos, franchise characters, product names presented as endorsement, or likenesses of real people. Inspiration may be named in the README only, with a no-affiliation note.
- **Licenses.** Code is Apache-2.0. Fonts, images and any third-party code must be licensed for redistribution (for fonts, OFL or similar); keep their notices and record them in `PROVENANCE.md` and `NOTICE`.
- **Words.** Actions keep AgentNet’s words; people, agents and receipts keep their meaning. A receipt never means work was done.
- **Accessibility.** Text at least 4.5:1 on its surface in both themes, visible focus, keyboard use, 44px touch targets on phones, movement only outside `prefers-reduced-motion: reduce`.
- **Package hygiene.** Every file the package uses is declared; nothing else ships in it. No logs, keys, screenshots or checksums inside a package.
